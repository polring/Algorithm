# 📊 정렬 알고리즘
> 정렬 알고리즘은 크게 두 가지로 나뉩니다.
> 1. **비교 기반 정렬 (Comparison Sort):** 원소들을 서로 비교하여 정렬 (bubble, select, insertion, Quick, Merge, Tim)
> 2. **비교 불가능 기반 정렬 (Non-comparison Sort):** 원소를 비교하지 않고 특성을 이용해 정렬 (count, radix)

---
## ⏱️ 정렬 알고리즘 종합 성능 비교표

| 정렬 알고리즘 | 평균 시간 복잡도 | 최악 시간 복잡도 | 공간 복잡도 | Stable 여부 | 특징 및 실전 요약 |
| :--- | :---: | :---: | :---: | :---: | :--- |
| **버블 (Bubble)** | $O(N^2)$ | $O(N^2)$ | $O(1)$ | **Yes** | 인접한 두 원소를 스왑. 구현은 쉽지만 가장 느림 |
| **선택 (Selection)** | $O(N^2)$ | $O(N^2)$ | $O(1)$ | No | 최솟값을 찾아 맨 앞으로 이동. 스왑 횟수가 적음 |
| **삽입 (Insertion)** | $O(N^2)$ | $O(N^2)$ | $O(1)$ | **Yes** | 데이터를 바른 위치에 삽입. **거의 정렬된 배열에서 최강 ($O(N)$)** |
| **퀵 (Quick)** | $O(N \log N)$ | $O(N^2)$ | $O(\log N)$ | No | 피벗 기준 분할. 대부분의 상황에서 평균적으로 가장 빠름 |
| **병합 (Merge)** | $O(N \log N)$ | $O(N \log N)$ | $O(N)$ | **Yes** | 반으로 쪼갠 뒤 합침. 최악에도 성능 보장, **투 포인터** 활용 |
| **팀 (Timsort)** | $O(N \log N)$ | $O(N \log N)$ | $O(N)$ | **Yes** | 삽입+병합 짬뽕. **Python(`sort()`), Java 내장 정렬 알고리즘** |
| **계수 (Counting)** | $O(N + K)$ | $O(N + K)$ | $O(K)$ | **Yes** | 빈도수를 카운팅. **데이터 범위($K$)가 작을 때 극단적으로 빠름** |
| **기수 (Radix)** | $O(D \times (N + B))$ | $O(D \times (N + B))$ | $O(N + B)$ | **Yes** | 일의 자리, 십의 자리 등 자릿수별 정렬. 부동소수점은 불가 |

*※ $K$: 데이터의 최댓값, $D$: 최대 자릿수, $B$: 진법(보통 10진법)*

*※ **Stable(안정 정렬):** 값이 같은 원소들의 원래 순서가 정렬 후에도 유지되는지 여부*

## 🔍 알고리즘별 핵심 매커니즘
### 1. 버블 정렬 (Bubble Sort)
- **원리:** 뒤에서부터 한 칸씩 이동하며 인접한 두 원소를 비교해 큰 값을 뒤로 보냅니다. 한 바퀴 돌 때마다 맨 뒤에 가장 큰 값이 고정됩니다.

### 2. 선택 정렬 (Selection Sort)
- **원리:** 전체 배열에서 최솟값을 찾아 맨 앞의 원소와 교환합니다. 그다음 두 번째 정렬되지 않은 구간에서 최솟값을 찾아 두 번째 원소와 교환하는 방식을 반복합니다.

### 3. 삽입 정렬(Insertion Sort)
- **원리:** 두 번째 원소부터 시작하여 앞의 정렬된 원소들과 비교하며 자신이 들어갈 적절한 위치를 '삽입'합니다. 성능은 $O(N^2)$이지만, 이미 데이터가 어느 정도 정렬되어 있다면 $O(N)$에 가깝게 작동합니다.

### 4. 퀵 정렬(Quick Sort)
- **원리:** 기준점(Pivot)을 정해 이보다 작은 그룹과 큰 그룹으로 쪼개나가는 분할 정복 방식입니다. 평균 성능이 매우 훌륭하지만 오름차순/내림차순이 이미 끝난 배열을 피벗으로 잘못 고르면 $O(N^2)$까지 성능이 저하됩니다.

### 5. 병합 정렬(Merge Sort)
- **원리:** 배열을 원소가 1개가 될 때까지 절반으로 쪼갠 뒤, 정렬하면서 다시 병합합니다. 최악의 경우에도 항상 $O(N \log N)$을 보장하는 탄탄한 알고리즘이며, 합치는 과정에서 투 포인터 테크닉이 사용됩니다.

### 6. 팀 정렬(Timsort)
- **원리:** 현실의 데이터는 대부분 '이미 정렬된 덩어리(Run)'가 섞여 있다는 점에 착안하여, 삽입 정렬과 병합 정렬을 영리하게 혼합한 알고리즘입니다.
- **실전 팁:** 파이썬 내장 정렬 함수인 sort()와 sorted()가 내부적으로 이 Timsort를 사용하므로 최악의 상황에도 완벽한 효율을 보여줍니다. 직접 구현하기 복잡하여 코테에서는 개념 위주로만 출제됩니다.

### 7. 계수 정렬 (Counting Sort)
- **원리:** 원소 간 비교를 하지 않습니다! 배열 내 원소들의 빈도수를 기록하는 별도의 카운트 배열을 생성한 뒤 그 정보를 바탕으로 정렬합니다.
- **주의:** 데이터의 범위가 작고 정수형일 때만 쓸 수 있습니다. (예: 100만 이하의 숫자 1000만 개를 정렬할 때 압도적 속도 발휘) 만약 데이터 개수는 2개인데 값이 1과 10억이면 메모리가 터집니다.
### 8. 기수 정렬(Radix Sort)
- **원리:** 계수 정렬의 한계를 극복하기 위해 나온 알고리즘으로, 가장 낮은 자릿수(일의 자리)부터 가장 높은 자릿수까지 자릿수별로 계수 정렬(Counting Sort)을 차례대로 수행합니다. 비교 정렬의 한계인 $O(N \log N)$의 벽을 깨부수는 알고리즘입니다.
