# Dynamic Programming

> **다이나믹 프로그래밍(DP)** 은 복잡한 문제를 한 번에 풀지 않고, **작은 문제들로 나누어 푼 뒤 그 결과들을 재사용(기억)** 하여 효율적으로 해결하는 알고리즘 설계 기법입니다.

## DP 적용 조건
아무 문제에나 DP를 적용할 수는 없으며, 반드시 다음 두 가지 조건을 만족해야 합니다.
1. **최적 부분 구조 (Optimal Substructure)**
    - 큰 문제의 최적의 답이, 작은 문제들의 최적의 답을 모아서 만들어질 수 있는 구조여야 합니다.
2. **중복되는 부분 문제 (Overlapping Subproblems)**
    - 동일한 작은 문제들이 반복해서 계산되는 경우여야 합니다.

## 🚀 핵심 접근 방식 비교
DP 문제를 해결하는 방법은 크게 두 가지 방향이 있습니다.

| 구분 | Top-Down (하향식) | Bottom-Up (상향식) |
| :--- | :--- | :--- |
| **개념** | 큰 문제부터 시작하여 위에서 아래로 내려가며 해결 | 작은 문제(기초 상태)부터 시작하여 차근차근 위로 채워나감 |
| **핵심 기법** | **Memoization (메모이제이션)**: 한 번 구한 답을 기억함 | **Tabulation (타뷸레이션)**: 표를 채워나감 |
| **구현 방식** | **재귀 함수 (Recursion)** | **반복문 (For Loop)** |
| **장단점** | 가독성이 좋으나, 재귀 깊이(Stack Overflow) 제한 위험 있음 | 함수 호출 오버헤드가 없어 **일반적으로 더 권장됨** |

## 🔥 자주 나오는 유형
- 0-1 배낭 문제 (0-1 Knapsack Problem)
- 가장 긴 증가하는 부분 수열 (LIS, Longest Increasing Subsequence)
- 최장 공통 부분 수열 (LCS, Longest Common Subsequence)
- 계단 오르기 / 피보나치 변형 (타일링 문제)
- 최소 편집 거리 (Edit Distance / Levenshtein Distance)

## 💡 DP 문제 풀이 3단계 전략
1. **DP 문제인지 확인하기**
   - 완전 탐색으로 풀기에는 시간 초과가 날 것 같고, 문제 안에 규칙성(부분 문제의 반복)이 보인다면 DP를 의심합니다.
   
2. **상태 정의하기**
   - DP 테이블(배열)의 인덱스와 값이 무엇을 의미할지 명확히 정의합니다.

3. **점화식 세우기**
   - 가장 중요한 단계로, $i$번째 값을 구하기 위해 이전 값들과 어떤 관계가 있는지 공식을 도출합니다.
